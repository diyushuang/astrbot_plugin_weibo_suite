# 指令手册

本手册面向群管理员与普通群友，说明本插件在 AstrBot 会话里注册的全部聊天指令：谁可以用、怎么传参、会得到什么结果。图片溯源与签到是散装顶层指令，微博监控与多平台订阅是分组指令，写法分别为 `微博 添加` 与 `订阅 抖音`。

指令前缀由 AstrBot 全局配置决定（默认可能是 `/`），插件只注册不带前缀的命令名，因此下文的 `溯源`、`微博 添加` 是否要加前缀取决于你的部署。别名通过 `@filter.command(alias={...})` 声明，与主名等价；`订阅` 族同时兼容 `订阅 登录 抖音` 与 `订阅登录 抖音` 两种写法，`微博` 族建议统一用空格分隔的写法。

管理员判定有两种实现，行为一致但拦截时机不同：

- 装饰器 `@filter.permission_type(filter.PermissionType.ADMIN)`：由 AstrBot 在分发前判定，非管理员通常收不到任何回复。本仓库绝大多数写操作属于此类。
- 处理器内 `event.is_admin()`：进入指令后才判定，可以按配置开关。目前只有 `登记原图`（受 `basic.register_admin_only` 控制，默认开）与 `签到文案导入` 属于此类。

指令注册集中在仓库根的 `main.py`，业务实现在 `weibo/commands.py`、`sns/commands.py` 与 `trace/` 下；模块拆分的原因是 AstrBot 按 `handler.__module__` 绑定处理器，装饰器写进子模块会让处理器失效。

另有 1 个不对应聊天指令的注册项：`@filter.llm_tool(name="sendRandomMedia")`，它是给 LLM 调用的工具（参数 `directory`、`content_type`），由模型在对话里自行决定是否调用，不受本文的权限规则约束，因此不列入下方指令清单。

## 图片溯源与签到

顶层 12 条指令，直接以命令名注册，不归属任何分组。

### /溯源

| 项 | 值 |
| --- | --- |
| 别名 | `找原图` |
| 权限 | 所有人 |
| 参数 | 无参数，需在消息里附图或引用一张图 |
| 是否需要 AstrBot 管理员 | 否 |

按 `basic.search_engine` 选定的引擎（`auto` / `vector` / `hash`）在本地图库与图床哈希索引里反查相似原图，命中后回传原图信息。`auto` 会优先试向量检索，不可用时回退哈希，两者都不可用会明确提示而不是静默失败。

**纯色/大面积平坦图按未命中处理**：这类图的 pHash 会退化成全零码，与任何同类图的汉明距离恒为 0，返回结果必是误报，所以查询侧直接返回空（`trace/library.py:505-511`，只在机器人日志里记一条 info），不会给你一堆不相干的「相似图」。

```text
溯源
```

### /登记原图

| 项 | 值 |
| --- | --- |
| 别名 | `原图登记` |
| 权限 | 默认 AstrBot 管理员，可由 `basic.register_admin_only` 放开 |
| 参数 | 无参数，需在消息里附图 |
| 是否需要 AstrBot 管理员 | 默认是 |

把一张图片登记进本地图库或图床哈希索引，作为后续溯源的命中源。它是少数在处理器内用 `event.is_admin()` 判定的指令，所以把 `basic.register_admin_only` 设为 `false` 后普通群友也能贡献素材；没有附带图片时会回显用法而不是记一条空记录。

**纯色或大面积平坦的图不会被登记**（`trace/library.py:269-276`）：它们的 pHash 退化为全零码，一旦入库，之后任意一张纯色图都会被判成「已登记过」。遇到这种图会直接回「⚠️ 这张图是纯色或大面积平坦图，感知哈希退化为全零码，无法与其它同类图区分，已跳过（不入库、不参与检索）。」，不会假装登记成功。

```text
登记原图
```

### /溯源状态

| 项 | 值 |
| --- | --- |
| 别名 | 无 |
| 权限 | 所有人 |
| 参数 | 无 |
| 是否需要 AstrBot 管理员 | 否 |

输出图库条目数、索引状态与当前引擎，用来确认「为什么溯源没有命中」是索引没建还是图库为空。

图床进入降级时，这里会多出一行「⚠️ 图床不可用（<模式>），自 MM-DD HH:MM 起登记已降级为本地副本；上传恢复后自动解除」。降级指的是：`image_bed` 上传在重试后仍失败，登记不会失败、只是改存本地副本——所以直链变成本地路径时先看这一行，不要以为是图床配置写错了（`trace/image_bed.py:238-258`、`trace/library_mixin.py:293-310`）。

```text
溯源状态
```

### /溯源重扫

| 项 | 值 |
| --- | --- |
| 别名 | 无 |
| 权限 | AstrBot 管理员 |
| 参数 | 可选关键字 `force`（不区分大小写） |
| 是否需要 AstrBot 管理员 | 是 |

重新扫描配置的本地图库目录并刷新特征索引。带上 `force` 会先清空已有的 scan 源再重建，适合大批量增删图片后索引与磁盘对不上的情况；不带 `force` 只做增量刷新。

进度里的「跳过」包含两类：与库里已有 pHash 重复的图，以及**纯色/平坦图的退化 pHash**（`trace/library_mixin.py:427-431`）。后者是刻意计入「跳过」而不是「失败」，否则「新增 + 跳过 + 失败」加不出总数，看起来像扫描漏了文件。

```text
溯源重扫 force
```

### /原图修复

| 项 | 值 |
| --- | --- |
| 别名 | 无 |
| 权限 | 所有人 |
| 参数 | 无 |
| 是否需要 AstrBot 管理员 | 否 |

清理会话历史里带装饰前缀的脏键。1.6.1 之前的版本会把配文前缀（`🖼️ `、`🎬 `、多图的 `1. `）连同文件名一起登记进历史，于是引用那条消息发 `/原图` 时，插件会拼出一个带前缀的 `/file/` 地址而必然 404。这个指令把旧键改名成干净形态（不是删除，直链本身是好的），只动内存里的会话历史，不动图床文件；没有脏键时会回「无需修复」。升级后遇到「引用那张图发 /原图 取不到」时跑一次即可。

```text
原图修复
```

### /微博 关键词相册

| 项 | 值 |
| --- | --- |
| 别名 | 无 |
| 权限 | AstrBot 管理员 |
| 参数 | `<关键词> <群号> <相册名或相册 ID>`，群内执行可省略群号 |
| 是否需要 AstrBot 管理员 | 是 |

全局关键词路由：微博正文命中关键词时，图片只传指定群的指定相册，替代相册绑定规则。关键词里不能含冒号。

群内省略群号时，关键词之后的词按三步判定目标群（`weibo/commands.py:181` 的 `_album_target_args`）：

1. 整段正好是本群**此前解析成功过**的相册名（上传时写入的内存解析缓存，TTL 1 小时，见 `weibo/album.py:269` 与 `ALBUM_RESOLVE_TTL`）→ 当前群 + 整段；
2. 首段是 **5 位以上**纯数字（QQ 群号最短 5 位）→ 当作群号；
3. 其余一律当**当前群**的相册名。

所以数字开头的相册名（如「2024 图集」「福利 123旅行」）不会再被误判成不存在的群，纯数字相册 ID 也留在本群。私聊没有上下文群，必须写群号，否则提示「私聊使用必须写明群号」。

```text
微博 关键词相册 摄影 1000000001 摄影相册
```

全量回填某博主的历史微博，逐页翻时间线按 mid 幂等入库，遇到风控或异常只暂停不抛错。参数是**命令行式解析**：`_parse_backfill_args` 在命令名之后的词里认 `--full` / `-f`、`--since=YYYY-MM-DD` 和 `--since YYYY-MM-DD`，uid 取第一个非 `-` 开头的 token（主页链接里的数字也会被识别）。

`since` 格式非法时直接报错「since 需形如 YYYY-MM-DD」而不是降级成全量，避免打成 `--since 2024` 这种少写一位的输入后默默跑满上限。省略 `since` 时回落 `archive.since` 配置；单次回填最多 1000 页，页间隔取 `archive.page_delay`（默认 3 秒）。是否写正文全文由 `--full` 控制。

**已经取到的全文不会被后续短摘要顶掉**：归档库的正文合并是「更长者胜，`text_full` 标记只升不降」（`weibo/archive_db.py:242-256`），`--full` 只在真拿到更完整正文（或等长覆盖）时才替换（`weibo/archive.py:387-393`）。所以时间线刷新、重复导入都不会把长文退回摘要，也不需要每次重跑 `--full` 保全文。

```text
微博 回填 1000000001 --since 2024-01-01
```
