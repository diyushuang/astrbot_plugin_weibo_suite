# 微博全链路助手

当前已完成 P1/P2/P3/P4/P5/P6/P8：图片溯源域、微博监控域、整条微博归档域、
图床向量管线、签到文案库、统一七页签 WebUI 与多平台（抖音 / 小红书 /
Instagram）订阅推送均已可用，统一入口可加载。

- 溯源与交付：`/溯源`、`/登记原图`、`/原图`、`/溯源重扫`、`/溯源删除`
- 媒体：`/随机图`、`/随机视频`、`sendRandomMedia`
- 签到：`/签到`、`/签到文案导入`
- 共享底座：SSRF 防护、IP 钉扎、受限流式下载、错误留存、NapCat 错误分类

微博监控：`微博` 30 条指令、免 Cookie 游客身份、推送队列、视频直发与群相册。

微博归档（P3）：`微博回填 <uid> [--since] [--full]`、`微博回填状态`、
`微博回填停止`、`微博归档导入 <文件>`、`微博归档查询 [uid] [页码]`、`微博对账 [uid]`。
帖子与媒体账本落在 `data_dir/archive.db`（SQLite WAL），原图落在
`data_dir/archive/<uid>/<mid>/`；监控命中即增量归档，原图旁路下载，回填支持
断点续跑与风控自动暂停。

图床/缩略图/向量管线（P4）：归档完成后自动入队（受 `pipeline.enabled`、
`pipeline.auto_queue`、`pipeline.enabled_uids` 约束），单帖一次走完原图上传 →
720px JPEG q72 缩略图 → pHash/向量入库。命名默认
`{category}/【微博图集@{account}】/` + `【微博@{account}】{date}-{index}：{title}.jpg`，
与现网同构，`/原图` 可按名直查；缩略图写入同一 Qdrant 点的 `thumb_url`。
六态进度（downloaded→album→bed→thumb→vector）落 `archive.db` 的 `media` 表，
断点续跑、单 worker 串行、失败退避 5→60s。对应指令：`微博管线状态`、
`微博管线补跑`（管理员）。CFB 图床模式只补原图落盘，其余状态交由图床侧钩子。

签到文案库（P5）：`archive.db` 的 `cleaned_text` 是唯一正文源，监控归档、回填和
CSV 导入都会按 mid 幂等落库；`/签到` weibo 模式直接读取该库，不再依赖人工生成
映射表。`微博文案库`、`微博文案列表`、`微博文案清洗`、`微博文案导出`、
`微博文案导入` 分别提供状态、检索、重建与交换入口。清洗使用与 Node 版逐字符
一致的 `weibo/cleaner.py` 和随包 `emoji-props.json`，90 条黄金样本及 2114 条
参考语料对拍零差异；归档不可用时仍回退旧 CSV/MD。

统一 WebUI（P6）：在 AstrBot「插件 → 微博全链路助手 → 详情页」打开，
提供总览、微博监控、归档与图床、文案库、溯源与签到、多平台订阅、
错误日志七个页签。
归档回填、对账、管线补跑、命名规则、文案导入、图库重扫与历史键修复都可在
面板操作；危险动作使用页内二次确认，后台任务可轮询进度。面板只调用与聊天
指令相同的业务入口，不复制业务逻辑。

多平台订阅（P8）：`订阅 抖音 <主页链接>`、`订阅 小红书 <主页链接>`、
`订阅 IG <用户名>` 即可订阅博主，有更新自动推到通知群；`订阅 列表`、
`订阅 状态`、`订阅 检测`、`订阅 演练`、`订阅 删除`、`订阅 帮助` 为管理入口，
`订阅 RSS <地址>` 留作"平台实在取不动"时的备选通道。抖音/小红书/IG 的时间线
接口都要求登录态，所以取数有三条通道（面板「取数通道」切换，也可按平台分别
配置）：

- `browser`（默认，最稳）：用 playwright 起一个持久化浏览器，你自己在那个
  窗口里登录一次，之后每次检查就是在同一会话里打开博主主页。Cookie 从不离开
  浏览器、不落盘、不进日志，TLS/指纹/出口 IP 与真人一致，风控压力最小。
  需要本机已装 Microsoft Edge（或 `playwright install chromium`）。
  首次使用：`订阅 登录 抖音` / `小红书` / `IG` 会弹出窗口，登录完回来
  `订阅 状态` 看到「已登录」即可。装完插件若提示缺 playwright，执行
  `pip install playwright`（pip 包不含浏览器内核，用系统 Edge 就不用再下载）。
- `http`：粘一份导出 Cookie 走纯 HTTP，快，但 TLS 指纹与浏览器不同，
  风控概率更高；抖音这条通道还必须能从 Cookie 里取到 `UIFID`（列表接口要签名）。
- `rss`：RSSHub 一类自建源，只解析，不碰平台风控。

保号是第一目标，默认参数都很保守：抖音/小红书基础间隔 300s、IG 900s，抖动只
往上加（绝不提前），0–8 点自动降速一倍，账号越多间隔线性拉长，新账号 30 分钟
热身、24 小时保号期，单轮最多推 3 条，只取首页不翻页、不查评论不查粉丝。
命中风控按信号加权指数冷却（小红书验证码 1.8 倍、抖音静默空响应 1.2 倍），
健康度低于 0.4 自动降速、低于 0.2 自动暂停；同一平台 10 分钟内 3 次风控则整
平台熔断 30 分钟；需要重新登录的账号只告警不自动重登，绝不反复撞验证码。
网络错误不计入风控计数（只有风控事件才冷却），空响应与结构不符一律按错误处理
——把它们当"没有更新"会掩盖风控，是最容易踩的坑。

延迟是这套保守参数的代价，且如实写在这里：抖音/小红书 P50 约 150s、P95 约
300s，IG P50 约 450s、P95 约 900s。面板里有「激进档」（120/180/300s）可以
自己打开，但提示会标红——那是在拿账号换速度。
